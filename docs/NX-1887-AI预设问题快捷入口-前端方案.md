## 一、需求摘要

在前台"主播私聊"聊天窗口的消息区底部叠加 AI 预设问题快捷入口卡片，帮助用户一键发送常见问题给主播/客服。

### 1.1 三态切换

| 状态 | 触发方式 | 表现 |
|---|---|---|
| 默认态（≤ 2 行） | 进入主播私聊，问题内容不多 | 卡片白底 + 「你可以这样问」+ items（自适应高度 60~110px）+ 右上 `×` |
| 默认态（> 2 行） | 内容超过 2 行 | 前 2 行渲染，第 2 行末尾拼「更多 &gt;」按钮 |
| 展开态 | 点击「更多 &gt;」 | 白底浮层 + 边框 + 阴影，252px 高，2 列固定网格，item 带 ↗ 箭头，超出滚动 |

### 1.2 关闭行为

- **默认态 `×`**: 关闭整块卡片；本次会话内不再展示。下次切会话 / 切 tab / 刷新页面 → 重新拉取并显示。
- **展开态 `×`**: 收起浮层，回到默认态。默认态始终保留在下方（未隐藏），因此切换无闪屏。

### 1.3 点击问题按钮

- 直接作为文本消息发送到主播私聊，等价于用户在输入框敲入该文案后点"发送"。
- 走 `operationPanel.sendMessage(MESSAGE_TYPE.TEXT, text)`，复用现有的游客校验 / 禁言校验 / `isReady/isSending` 校验 / `pm_source_type` / seed 生成。
- **不**传 `ai_message_id` 或任何 AI 参数（后端方案里 `ai_message_id` 仅用于后台客服采用 AI 回复建议的场景）。
- **不**做点击埋点接口调用，后端通过 `sendMessage` 链路自动统计 `use_count`。

### 1.4 数据刷新时机

进入主播私聊 / 切换会话（`vid` 或 `uid` 变化）/ 页面刷新时重新拉取。无 WebSocket 实时推送需求。

## 二、后端接口

后端接口 `/chatAi/category/list`，走 vite 代理必须补 `/api/` 前缀（`vite.config.ts:184-198` 只转发 `/api/`、`/bbs/`、`/upload/`）。

```
GET api/chatAi/category/list

Response: {
  code: number,
  data: Array<{
    id:   number   // 问题 ID
    text: string   // 问题内容
    sort: number   // 排序，值越大越靠前
  }>
}
```

- 无分页，一次性返回全量。
- 前端按 `sort` **降序**排序。
- 失败时静默降级：`list = []`，卡片不显示（与 `pinData` 缺失时处理一致）。

### 3.2 AiPresetQuestions（主组件）

**Props**

| 名称 | 类型 | 说明 |
|---|---|---|
| `chatType` | `number` | 门槛判断；仅 `ANCHOR_PRIVATE (-2)` 时才拉取渲染 |
| `vid` | `string` | 会话 key |
| `uid` | `number` | 会话 key |
| `isReady` | `boolean` | 未就绪时按钮置灰 |
| `isMute` | `boolean` | 禁言态按钮置灰 |

**Emit**

| 事件 | 载荷 | 用途 |
|---|---|---|
| `select` | `text: string` | 父组件调用 `sendMessage` 发送 |
| `visibility-change` | `{visible, expanded}` | 父组件调整 padding-bottom / 悬浮按钮位置 / 触发贴底 |

**内部状态**

```ts
const list         = ref<AiCategory[]>([])
const closed       = ref(false)          // × 关闭态
const expanded     = ref(false)          // 「更多」浮层态
const visibleCount = ref(0)              // 默认态可见 item 数（measure 得出）
const visible      = computed(() =>
  !closed.value &&
  props.chatType === CHAT_TYPE.ANCHOR_PRIVATE &&
  list.value.length > 0
)
const hasOverflow  = computed(() => visibleCount.value < list.value.length)
```

**两行测量算法（保证严格 ≤ 2 行）**

见「代码改动清单」文档 5.2 节的完整实现。核心思路：
1. 先按全量渲染，遍历 `[data-ai-item]` 的 `offsetTop`，找出第 3 行第一个元素的下标。
2. 若发生溢出，`visibleCount = firstThirdRowIdx`，让「更多 &gt;」按钮进入 DOM。
3. 迭代往前踢，直到「更多 &gt;」和保留 item 都在前 2 行。
4. `ResizeObserver` 只在**宽度**真正变化时重跑（不响应自身高度变化，避免死循环）。

### 3.3 PresetBtn（按钮组件）

**Props**

| 名称 | 类型 | 说明 |
|---|---|---|
| `text` | `string` | 问题文本 |
| `disabled` | `boolean?` | 禁用态 |
| `variant` | `'row' \| 'grid'?` | `row`：默认态紧凑药丸；`grid`：展开态占列宽 + ↗ 箭头 |

**截断 tooltip**：`mouseenter` 时懒检测 `scrollWidth > clientWidth`，只在真截断时挂 `el-tooltip`。参考仓库先例 `tabsWorkBench/index.vue:29`。

**为什么单独抽组件**：之前把 pill 样式挂在主组件循环的 wrapper 上，因为 wrapper 是 `<el-tooltip>`，class fallthrough 落到 el-tooltip 根节点而非 `<button>`，导致 `inline-flex / max-width` 等样式全部丢失。抽出后样式 self-contained 在真正的 `<button>` 上。

### 3.5 浮层定位（chatDetail）

`.chat_detail_comp` 是 `position: relative`（`chatDetail:807`），是绝对定位锚点。

**默认态**：贴操作面板顶部，左右满宽（等同于占用消息区底部空间）
```ts
bottom: opPanelH + 'px'
left:   '0'
right:  '0'
```

**展开态**：距工具栏 10px，左右各留 8px 空隙（视觉居中）
```ts
bottom: opPanelH + 10 + 'px'
left:   '8px'
right:  '8px'
```

`opPanelH` 通过 `ResizeObserver` 从 `operationPanelRef.value.$el.offsetHeight` 读取，兜底 88。

### 3.6 遮挡与滚动补偿

**默认态**：消息区加 `padding-bottom = 卡片实际高度`，确保滚到底时最后一条消息不被遮挡。

**展开态**：不加 padding（按需求，用户主动打开浮层就是暂时不看消息，遮挡合理）。

**贴底补偿**：卡片可见性/态位变化时：
1. 先读 `useScrollReturn.arrivedState.bottom`（此时是变化**前**的状态）
2. 更新 `aiCardVisible / aiCardExpanded`
3. `nextTick` 里读卡片实际高度、更新 `aiCardHeight`
4. 手动 `useScrollReturn.measure?.()`（`useScroll` 只在 scroll 事件更新，不监听 resize）
5. 若原本贴底 → `scrollToLastMsg()`

**「新消息」/「回到底部」按钮**：`bottom` 从 CSS 硬编码 `94px` 改成动态 `94 + 卡片高度`（展开态回到 94）。

### 4.1 直接受影响

| 文件 | 变更 | 风险 |
|---|---|---|

### 4.2 间接受影响 / 需回归

| 场景 | 说明 |
|---|---|
| 消息发送链路 | 复用 `operationPanel.sendMessage`，未改动。回归：文本 / 图片 / 视频 / 表情 / 主播私聊 / 广场 / 群组 / 全局悬浮 / 论坛 |
| 消息区滚动 | 默认态用 padding-bottom 补偿；`arrivedState.bottom` 判定不受 padding 影响（`clientHeight` 是 padding box） |
| 「新消息」/「回到底部」按钮位置 | 从 CSS `bottom:94px` 改为动态 `:style`，跟随卡片高度抬起；卡片关闭恢复 94 |
| 悬浮按钮 z-index | `.ai_preset_overlay: z-index: 998`；`.has_new_message: 1000`；`.scroll_to_bottom_btn: 999` —— 通知类按钮仍在卡片之上 |
| `.gift_container` | 只在 `chatType === PUBLIC` 显示（`chatDetail:52`），与本卡片（`ANCHOR_PRIVATE`）永不共存，`bottom: 88px` 硬编码不受影响 |
| ChatBox 三个消费方 | 直播间 / 全局悬浮 / 论坛均通过 `props.chatType` 层层透传，一处生效即三处生效；只有 `chatType === ANCHOR_PRIVATE` 场景显示 |
| 虚拟房间切换（`change-vid`）| `chatBox:74` 的 `anchorVid` 变化会带动 `props.vid` 变化，触发 `watch` 重新拉取 |
| 网络异常 | `list = []` 静默降级，不显示卡片、不弹 toast |
| 禁言态 | `isMute` 传入卡片，按钮置灰不可点 |
| 未就绪态（`isReady=false`）| 按钮置灰，避免触发 sendMessage 内部的「消息正在加载中」提示 |

### 4.3 后端依赖

- 前端依赖 `GET api/chatAi/category/list`，此接口需后端先上线。
- 若后端未 ready，`list = []` 卡片不显示，页面不受影响。
- `sendMessage` 新增的 `ai_message_id` 参数与本功能**无关**，前端不使用。

### 4.4 不改动的内容

- `src/utils/request.js`（obfuscated）与 `src/utils/request-o.js` 不动
- `getQuickReplyList / addQuickReply / delQuickReply`（客服快捷回复）不复用不合并
- WebSocket / IM 事件流不动
- `sendMessage` / `sendData` / `keyDown` / `sendTextMsg` / `scrollToLastMsg` 本体一行不动
