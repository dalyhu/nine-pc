## 零点五、影响范围控制（稳定优先）

**四条原则**：

1. **只在现在会白屏、会卡死的地方介入。** 现在能正常显示的页面，行为一律不变。
2. **不改全站配置，不动业务代码。** 新逻辑都放在新文件里，接入点尽量少。
3. **每个任务可以单独回退。** 一个任务一个提交，出问题直接 `git revert` 那一个提交，不牵连其他任务。

**逐项收窄**：

### 2.2 Vue 3.4 的错误传递（读 `@vue/runtime-core@3.4.0` 源码确认）

- **传递顺序**：组件报错后，Vue 先从出错组件的父组件开始，逐层调用 `onErrorCaptured`。有一个钩子返回 `false` 就停止传递；否则最后交给 `app.config.errorHandler`。
- **生产环境的 `info` 参数**：形如 `https://vuejs.org/errors/#runtime-<错误码>`。
  - 生命周期钩子的错误码是字符串，比如 `m`、`bm`。
  - 开发环境里 `info` 是文字描述。
  - 所以解析时要同时兼容三种形式：数字、字符串、URL。
- **`return false` 的效果**：只是阻止继续往上传，不会自动卸载或重建出错的组件。所以错误边界要自己用 `v-if` 把原内容整个换掉。
- **调度器的错误（码 14）**：报错时组件实例是 `null`，不经过 `onErrorCaptured`，也不进 `errorHandler`，只会打日志。这类错误不在兜底范围内。

**按错误码分两类处理**：

| 错误码 | 类型 | 处理 |
|---|---|---|
| 0 | setup 同步报错 | **致命**，显示错误页 |
| 1 | 渲染，含首次渲染和更新渲染 | **致命** |
| 9 | transition 钩子 | **致命**，AppMain 用了 out-in，钩子出错页面会停在空白 |
| 13 | 异步组件加载 | **致命** |
| `bc` `c` `bm` | 创建、挂载前的生命周期钩子 | **致命**，组件可能没有渲染出来 |
| 5、6 | 原生事件、组件事件回调 | 只记录，页面不受影响 |
| 2、3、4 | watch | 只记录 |
| `m` `u` 等其他 | 挂载后的生命周期钩子、指令、ref 等 | 只记录，内容已经渲染出来了 |

不认识的错误码按「只记录」处理，宁可少拦，也不把正常页面换成错误页。**T1 要在生产构建里逐类注入错误，实测这张表。**

**异步 setup 不在兜底范围内，改为禁用**：

- 异步 setup 指 `<script setup>` 顶层写 `await`，或者 `async setup()`。
- 没有 `<Suspense>` 时，Vue 会把它 reject 的错误吞掉，不经过 `onErrorCaptured`，组件直接什么都不渲染。
- 项目现在一处都没用，也没用 Suspense（2026-11-10 全量检查过）。
- 所以写进 CLAUDE.md 禁用：异步数据放到 `onMounted` 里，自己 try/catch。

**① 兜底脚本开放 API（改 `index.html`）**

- `showError()`：进入「运行期错误」模式。

**③ 页面级错误边界：`src/components/PageErrorBoundary/index.vue`**

- 用 `onErrorCaptured(err, instance, info)` 捕获错误，**先 `record`，再判断要不要介入**。所有错误都 `return false`，不再往上传，避免重复记录。
- **只有同时满足下面两条，才显示错误页**；不满足就只记录，页面保持现状：
  1. `isFatalVueError(info)` 为真（渲染类错误，作为初筛）；
  2. `nextTick` 之后看**结果**：`route.matched` 第 1 层及以下（第 0 层是 Layout）各级的页面实例，有一个什么都没渲染出来（实例不存在、没有根节点，或根节点是注释节点）。
  - **T1 实施中的更正**：原设计按「出错的是不是页面组件本身」判断，生产构建实测有两个反例，所以改为看渲染结果：
    - 选项式组件 setup 报错后，Vue 仍会用模板渲染，页面完好，原判断会误伤；
    - 插槽里的报错会算到渲染插槽的子组件头上（比如 `el-scrollbar`），原判断会漏掉。
  - 例子：页面里某个卡片组件渲染报错，页面其余部分照样显示。现在是这样，改完还是这样，只是多了一条诊断记录。
- 模板用互斥分支：`<PageError v-if="error || pageError.value" />`，否则 `<slot v-else />`。出错时原页面会被卸载。
- 边界组件不额外渲染包裹元素。PageError 只在出错时渲染，所以正常页面的 DOM 结构和样式完全不变。
- **共享状态 `src/utils/pageError.js`**（T1 建好，T2 才往里写）：
  - 导出一个 `ref(false)`，以及 `setPageError()`、`clearPageError()` 两个函数。
- **怎么恢复**：在 `router.afterEach`，也就是导航成功之后，同时清掉本地 `error` 和共享的 `pageError`。在错误页上点当前页面的菜单时，vue-router 会判定为重复导航（duplicated），这种情况也清除（T2 实测补充）。
  - slot 里的 `<component :key>` 已经按路由设置了 key，换路由时页面组件会重新创建。
  - 错误页上提供「返回首页」和「刷新页面」两个按钮。连续出错时，刷新就是最后的恢复手段。

**⑤ 全局 `errorHandler`（改 `src/main.js`）**

能走到这里的错误，说明页面级边界没有拦住，出错位置在 App、Layout 或全局组件里。

**⑥ 分包加载失败恢复：`src/utils/chunkReload.js`（纯函数 + 薄的接入层）**

Vite 5.0 的实际行为（源码 `vite/dist/node/chunks/dep-T98iZFpD.js:64234`）：

- 动态 import 失败时，派发一个可取消的 `vite:preloadError` 事件，原始错误在 `event.payload` 里。JS 文件加载失败和 CSS 预加载失败都会走这里。
- 如果调用了 `preventDefault()`，**import 的 Promise 不会 reject，而是 resolve 成 `undefined`**；没调用的话，原错误照常抛出，router 会走到 `onError`。

所以只在 `vite:preloadError` 这一个入口里决定要不要刷新：

```
收到 vite:preloadError
 ├ 不在路由跳转中（弹窗等非路由的 import）
 │   → 只记录，不 preventDefault，错误照常抛给调用方（和现在完全一样）
 ├ 在路由跳转中，能读写 sessionStorage，且 60 秒内没有刷新过
 │   → 写入时间戳 → preventDefault() → location.reload()（整页拿新版本）
 └ 否则（60 秒内刷新过 / 存储不可用 / 时钟异常）
     → 不 preventDefault，错误照常抛出
     → router.onError 收到 → pageError = true → 页面主体显示错误页
```

- **防循环**：
  - 时间戳差值小于 0（时钟被回拨）也当成「刚刷新过」处理。
  - sessionStorage 读写一律包 try/catch，不可用时**直接不自动刷新**，所以不可能死循环。
  - 用 `location.reload()`，不用 `to.fullPath`：这个事件拿不到路由目标。router 通常还没完成跳转，地址栏停在原页面，刷新后用户需要再点一次。这是取舍：稳定比少点一次重要。
- **刷新进行中**：
  - `preventDefault()` 之前，先把原始错误 `record` 下来，再设置模块内的 `reloading = true`。
  - `location.reload()` 不会让当前脚本马上停下来。这段时间里：
    - 再收到的 `vite:preloadError`：直接 `preventDefault()` 吞掉，不重复刷新，所以多个分包同时失败也只刷新一次；
    - `router.onError`、错误边界收到的错误：只记录，不显示错误页，避免刷新前闪一下错误页。
  - import 拿到的是 `undefined`，router 可能因此报「组件无效」，同样被上面这条吞掉。
  - 不是路由触发的 import，调用方会拿到 `undefined`。页面马上就要刷新，可以接受。
- **`router.onError(err)`**：
  - 先 `record`。
  - 不在刷新中，并且是分包加载错误时，调用 `setPageError()`。分包加载错误由 `isChunkLoadError` 判断，按文案匹配三家浏览器和 CSS 预加载失败。
- **怎么判断「在路由跳转中」**：
  - `router.beforeEach` 时设为 true；`afterEach` 和 `onError` 时设为 false。
  - 应用启动时的首次导航，也会经过 `beforeEach`。
- **不是路由触发的动态 import**（比如弹窗组件）：只记录，行为和现在一样，不会因此刷新页面。

### 2.4 验证（在生产构建里做，dev 模式下错误格式不同）

| 场景 | 期望 |
|---|---|
| 页面组件 setup 同步 throw / 首次渲染 throw / 更新渲染 throw | 页面主体是错误页，导航可用；换个菜单能恢复；复制的诊断信息里有这个错误 |
| 页面里某个子组件（比如直播间的一个卡片）渲染 throw | **页面其余部分照常显示，不出现错误页**；诊断信息里有记录 |
| 导航栏组件渲染 throw | 不出现整页兜底；诊断信息里有记录 |
| 弹窗等非路由的动态 import 加载失败 | 不刷新页面，行为和现在一致；诊断信息里有记录 |
| 复制诊断信息时，URL 带 `token`、`userId` | 复制出来的内容里没有这两个参数 |

## 五、R11 软性升级提示条

### 5.1 阈值在构建时算好

**环境变量**（`env/.env.prod` 等），缺失、不是正整数时直接让构建失败：

```
VITE_UPGRADE_BANNER=off              # on 才显示
VITE_UPGRADE_BANNER_BEHIND=4         # Chrome/Edge/Firefox：落后最新版几个版本开始提示
VITE_UPGRADE_BANNER_SAFARI_MAJORS=2  # Safari：保留最近几个大版本
```

**计算方法**（在 `vite.config.ts` 里，用 browserslist 的结果，不自己做减法）：

- **Chrome、Edge、Firefox**：
  - 执行 `browserslist('last <BEHIND+1> chrome versions')`，得到已发布的稳定版列表。
  - 去掉 TP、preview 等非稳定版后，取列表里最旧的那个作为阈值。
  - 低于阈值就显示提示条。
  - 例：最新 140、BEHIND=4，得到 140～136，阈值 136，Chrome 135 及以下会显示。
- **Safari**：
  - 执行 `browserslist('last <SAFARI_MAJORS> safari major versions')`，按发布顺序取大版本号，去重后取最旧的那个。
  - 不用「最新大版本减 1」：Safari 从 18 直接跳到了 26，做减法会算错。
- **注入方式**：结果通过 `define` 注入 `__X9_UPGRADE_BANNER__`；开关关闭时注入 `null`。
- **构建日志**：打印一行输入的版本列表和最终阈值，方便核对。
- 阈值计算抽成纯函数，写边界单测。

**数据会变旧**：最新版的数据来自 caniuse-lite，要按季度更新，写进 CLAUDE.md。即使数据旧了，结果也只是阈值偏低、显示的人变少，不会误伤。

**备选方案**（T6a 因为产物有变化而放弃更新 caniuse-lite 时启用）：

- 不再从数据里算阈值，改为在环境变量里直接写各浏览器的阈值版本：

  ```
  VITE_UPGRADE_BANNER_MIN=chrome:136,edge:136,firefox:140,safari:18
  ```

  数值只是示例，以实施当天各浏览器的最新版往前数 4 个版本来定。
- 这样对产物零影响，代价是每个季度要人工改一次这几个数字。
- 两种方案只启用一种：配了 `VITE_UPGRADE_BANNER_MIN` 就用它，没配就按数据计算。

### 5.2 判断逻辑：`src/utils/upgradeBanner.js`（纯函数）

```
shouldShow({ ua, maxTouchPoints, thresholds, closedAt, now }) → true / false
```

依次检查，任何一条不满足就不显示：

1. 开关关闭（`thresholds` 为 null）。
2. 兜底页已经显示（`window.__X9_UNSUPPORTED__`）。
3. 不是桌面端：
   - `UA_INFO.device.type` 有值，不显示。
   - UA 里有 `Macintosh` 且 `navigator.maxTouchPoints > 1`，这是 iPad 的桌面模式，不显示。
4. 浏览器名规范化之后不在白名单：
   - 白名单：`Chrome`、`Edge`、`Firefox`、`Safari`。
   - 微信、搜狗、QQ、360 等名字不在白名单。
   - 识别不出来的一律不显示。
5. 版本号取主版本数字比较，不低于阈值就不显示。版本号解析失败也不显示。
6. 7 天内用户主动关过：读 localStorage 的 `x9-upgrade-banner-closed`。读写包 try/catch，读不到时当作没关过。

UA 用 index.html 里已经解析好的 `window.UA_INFO`，不重复解析。
