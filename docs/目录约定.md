# PC 站目录与放置约定

> 状态：**已确认**（2026-11-19 用户确认）。核对基准：`pc-main` 的 `main`（`24693401`），2026-11-19。
> 适用对象：在 `pc-main`（Vue 3 + Vuex + Vite）里写**新代码**的 AI 会话和同事。
> 目的：新代码不再重复造轮子、不乱放。**已上线的旧代码一律不动**，本约定只管新写的部分。
> 与仓库 `CLAUDE.md` 的目录表一致；冲突时以 `CLAUDE.md` 的「不能动的地方」为准。
> 本文是统筹目录维护版本的副本（2026-11-19 随 NX-2151 复制）。约定有更新时以统筹目录的版本为准，再同步到这里。

## 2. 放置规则

| # | 类别 | 放哪里 | 具体规则 |
|---|---|---|---|
| 1 | 工具函数（纯函数） | `src/utils/<主题>.js` | 按主题一个文件（`date.js`、`number.js`、`url.js`、`storage.js`、`device.js`）。不新增到 `index.js`、`common.js`。旁边写 `<主题>.test.js`（`node:test`，**不要用 `@/` 别名**，用相对路径，否则 `pnpm test` 跑不了） |
| 2 | 带状态逻辑 | 多页共用：`src/composables/useXxx.js`；只有一个页面用：`src/views/<页面>/hooks/useXxx.js` | 文件名 `useXxx`，返回 ref / computed / 方法。不再新增 mixin |
| 3 | 公共组件 | `src/components/<PascalCase>/index.vue` | 至少两个页面会用才放这里。放之前先查 `src/components/` 有没有同类（空状态 `dfEmpty`、弹窗 `dfDialog`、图片 `dfImage` 等） |
| 4 | 页面私有组件 | `src/views/<页面>/components/<PascalCase>.vue` | 只有该页面用。新建用 `components/`，不要再用现有的 `component/`、`modal/` 写法 |
| 5 | 接口 | `src/api/<业务>.js` | 同业务已有文件就加方法，没有再新建。页面里不直接用 axios，不在 `.vue` 里拼接口地址 |
| 6 | 常量与枚举 | `src/enums/<主题>.ts`，在 `src/enums/index.ts` 里汇总导出 | 多处用的常量、状态码、类型值都放这里；只在一个文件内部用的常量留在该文件顶部，并写注释说明含义 |
| 7 | 类型 | 跟着所属主题走：写在对应的 `.ts` 文件里 | 多个文件共用的类型放 `src/enums/<主题>.ts` 或 `src/utils/<主题>.ts`；全局声明才放根目录 `types/global.d.ts`。目前没有 `src/types/`，不为单个类型新建目录 |
| 8 | `localStorage` / `sessionStorage` 的 key | key 常量集中在 `src/enums/storage.ts`；读写集中在 `src/utils/storage.js` | 两个文件现在都不存在，**第一个需要的人新建并登记**。新 key 命名：`x9-pc:<主题>`，带用户维度写 `x9-pc:<主题>::<userId>`；PC 与 H5 共享的写 `x9-web:<主题>`（参照 `botVerification.ts`）。旧 key（`userInfo`、`channel` 等）不改名 |
| 9 | 样式 | 组件内：`<style scoped lang="scss">`；全局：`src/styles/` | 颜色用 `theme.scss` 的 CSS 变量，同时给暗色主题（`html.dark`）写样式；新代码避免 flex `gap`、`dvh`、`:where()`（见 `CLAUDE.md` 兼容一节） |
| 10 | 静态资源 | 图片 `public/static/images/`，图标 `public/static/icons/`，字体 `public/static/fonts/`，音频 `public/static/audios/` | 文件名用英文、不含空格和中文（PWA 要求）。只有一个组件用的小图可以放组件同目录并 `import`，不要放进 `src/` 其他目录 |

## 3. 判断流程

新写一段代码，按顺序问：

1. **别的页面会不会用到？**（现在就有第二个使用方，或明显属于通用能力：格式化、登录态、存储、复制、URL 参数等）
   - 会：先看第 6 节「首选函数清单」和 统筹目录维护的公共逻辑登记表、再 grep `src/utils`、`src/composables`、`src/components`。
     有就直接用；没有，按第 2 节规则放到公共目录，并在登记表里加一行。
   - 不会：放 `src/views/<页面>/` 下（第 2 节规则 2、4）。
2. **是接口、常量、类型、存储 key 吗？** 是：按第 2 节规则 5–8，不管几个页面用，都放到固定位置。
3. **不确定？** 先放页面目录，等第二个页面要用时再搬到公共目录，不要为了「以后可能复用」提前放进公共目录。
4. 放哪里依据第 2 节哪一条，写进技术方案的「复用检查」。

## 4. 新建文件

- **同主题已有文件就加进去**：例如日期函数先看 `src/utils/date.js` 是否存在，存在就加，不存在才新建。
- 没有对应主题文件，按主题新建，**不按页面、不按需求命名**（不要 `src/utils/nx2146.js`）。
- **杂物文件 `src/utils/index.js`、`src/utils/common.js` 不再新增导出。** 可以从里面 `import` 现有函数（第 6 节指定的首选可以继续用），但新函数不往里加。
- 新建公共文件时，同一个提交里补：测试（纯函数）和 `公共逻辑登记.md` 的一行。
- 新建文件前先在第 6 节同义名字模式里 grep 一遍，确认没有已有实现。

## 5. 命名

- 工具文件：`src/utils/` 下小驼峰、按主题（`date.js`、`storage.js`）；TS 用 `.ts`。
- 组合式函数：`useXxx`，文件名同函数名（`useIsLogin.js`）。
- 组件：新建一律 PascalCase（目录 `ConfirmDialog/index.vue` 或文件 `ConfirmDialog.vue`）。旧目录里 `dfXxx`、`AuthDialog` 混用，不改，也不照着旧的 `df` 前缀新建。
- 函数：动词开头（`formatDate`、`getXxx`、`isXxx`），布尔值用 `is/has/can` 开头。
- 常量：`UPPER_SNAKE_CASE`；枚举成员同。
- **禁止同名不同义**：现在 `formatDate` 在 `utils/index.js:320`（相对时间「3天前」）和 `utils/common.js:30`（`dayjs` 格式化）是两个意思相反的函数，别再制造这种情况。新函数名先在仓库里 grep，已被占用就换名。
- 禁止用 `2`、`1` 之类后缀区分版本（旧有 `formatTime2`、`timeStamp1`），需要新行为就起新名字。

### 6.2 每类的现有实现与理由

**日期时间格式化**

| 现有实现 | 结论 | 说明 |
|---|---|---|
| `utils/common.js:30` `formatDate(timestamp, format='YYYY-MM-DD HH:mm:ss')` | **首选** | 用 `dayjs`，秒级（10 位）和毫秒级时间戳都认，格式串自定义；目前被 `mySpace` 下 3 个页面引用 |
| `utils/common.js:272` `formatDateLine`、`:25` `getYMD`、`:378` `getFormDate`、`:51` `timeStamp`、`:66` `timeStamp1`、`:36` `formatNewsTime`、`:15` `getToday` | 不要再用 | 都是 `formatDate` 的特例，格式写死或只认秒级；要「今天」用 `dayjs().format('YYYY-MM-DD')` |
| `utils/index.js:95` `parseTime`、`:196` `formatTime`、`:420` `formatTime2` | 不要再用 | 三种格式占位符（`{y}`、`yyyy`）与 `dayjs` 不同；`formatTime2` 被 6 个文件以别名 `formatTime` 引用 |
| `utils/index.js:320` `formatDate(dateTimeStamp)` | 不要再用 | **与 `common.js` 同名不同义**（相对时间，只认秒级）；只有 `views/member/feedback.vue` 引用，导入时注意路径 |
| `utils/index.js:359` `formatSeconds` | 例外 | 这是「秒数转时长」，不是日期格式化，仍可用 |
| 「几分钟前」类相对时间 | **暂无首选** | 现有两个实现（`utils/index.js:196` `formatTime`、`:320` `formatDate`）语义互不一致。新代码请在 `src/utils/date.js` 新建并登记 |

理由：同一个时间戳要给出一致的展示，先统一成一个入口；`formatDate` 有格式参数、依赖已在项目里的 `dayjs`。

## 7. 禁止事项

1. **页面和组件里直接读写 `localStorage` / `sessionStorage`**：走 `src/utils/storage.js`（尚未建，第一个需要的人新建），key 用常量。`src/store/` 里已有的写法不动。
2. **新增魔法数字**：状态码、类型值、时长、阈值等有含义的数字，写成有名字的常量（枚举放 `src/enums/`，文件内部的放文件顶部并写注释）。`0`、`1`、`-1` 做自增或判空不算。
3. **复制已有组件改几行**：要在已有组件基础上变一点，先给原组件加 `props` / 插槽，不要整份复制再改。已有的重复（`mySpace` 与 `otherSpace`、比分页各 tab）不在本约定处理范围。
4. 往 `src/utils/index.js`、`src/utils/common.js` 加新导出。
5. 页面里直接用 `axios`，或在 `.vue` 里写接口地址。
6. 同名不同义（见第 5 节），以及 `formatTime2`、`timeStamp1` 这种数字后缀命名。
7. 新增 mixin（`src/mixins/`）。
8. 动 `src/utils/c/`、`src/store/c/`、`request.js`、`request-o.js`。

## 8. 旧代码说明

- **旧代码的写法不代表规范，以本约定为准。** 仓库里随处可见的写法（页面里直接用 `localStorage`、各写一份 `isLogin`、`formatTime2`、`$message`）都不是模仿对象。
- 改到旧文件时**只改需求要的部分**，不顺手重构、不顺手搬函数、不统一改名。
- 在旧文件里新写的那几行，按本约定写：用第 6 节的首选，不再往杂物文件加导出，不新增魔法数字。
- 看到旧代码里的问题（比如 `assignDeep`），不顺手修，写进「发现的问题」交统筹登记。
