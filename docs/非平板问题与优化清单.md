- **证据**：`src/views/score/detail1.vue` 第 293 行模板里的「热火队」是固定文本；第 829 行起有固定的「雄鹿」和统计数值。旧分支验收时在普通 PC（1440×900，未启用平板作用域）上同样复现，原始基线已存在，与平板无关。
- **建议**：确认接口是否提供对应字段后，改为显示当前比赛的球队与统计；无数据时用业务认可的空态。数据来源与适用赛事需产品确认。
- **处理结果**：—

### OPT-02 手机上网页全屏中主播关播，可能无法退出全屏

- **项目 / 页面**：H5 / 直播间（`pages/live/components/detailRoot.vue`）
- **现象（推演）**：网页全屏中主播关播时，iframe 因 `liveClosed` 被 `v-if` 销毁（第 36 行），但 `handleLiveClosed`（第 1100–1112 行）没有重置 `isH5Fullscreen`。返回按钮走 `exitH5Fullscreen`，只给已不存在的 iframe 发消息，`handlePostMessage` 在 iframe 不存在时直接返回（第 1323–1324 行），页面可能停在全屏样式。
- **平板上的同类问题**：已纳入平板适配 T9，只对平板处理（关播时退出全屏）。
- **建议**：先在手机上复现确认。修复方向：关播或 iframe 不存在时，直接清理父页面的全屏状态。需回归手机全屏的进入与退出。
- **处理结果**：—

### OPT-03 浏览器名或系统名识别不出来时，设备信息整体初始化失败

- **项目 / 模块**：H5 / `plugins/init.client.js` 的 `initUA()`（第 14–36 行）
- **状态 / 影响**：已确认 / 中高。
- **来源**：本次代码阅读；tablet-h5 用 `ua-parser-js` 1.0.37 实测 OpenHarmony UA 复现。
- **现象**：鸿蒙 NEXT 的 UA（如 `Mozilla/5.0 (Phone; OpenHarmony 5.0) ...`）解析结果 `os` 为空，`initUA` 在第 20 行调用 `ua.os.name.includes(...)` 时抛 `TypeError`。同函数还直接调用 `ua.browser.name.includes(...)`，系统或浏览器名为 `undefined` 时都会抛错。错误被 `catch` 吞掉后，`window.UA_INFO` 停留在第 11 行的空对象 `{}`，后续的 `IS_PC`、`IS_MOBILE`、`IS_IOS` 等全部为 `undefined`：
  - 鸿蒙 NEXT 手机上依赖 `IS_MOBILE` 的逻辑（如直播间网页全屏）可能失效。
  - 电脑上冷门浏览器打开 H5 时不会被送回 PC。
  - 依赖 `UA_INFO` 的 iOS 缩放拦截、设备信息上报（`store/index.js` 第 289 行起）等都会失效或走异常分支。
- **建议**：对每个字段单独兜底（如 `(ua.os.name || '').includes(...)`），避免一个字段缺失导致整体失败。需回归手机各浏览器的分流与设备判断。
- **与平板的关系**：平板识别已改为单独解析 UA，不依赖 `UA_INFO`（tablet/03 T2），所以鸿蒙 NEXT 平板在四个生效页面不受该初始化失败影响；`initUA` 本身一期不修。
- **处理结果**：—

### OPT-07 电脑浏览器打开 H5 开发服务会反复跳转

- **项目 / 模块**：H5 / 本地开发环境

- **与平板的关系**：平板适配的本地测试已绕开此问题：平板在 H5 生效页面会留在 H5（tablet/04 第一节的测试环境说明）。
- **处理结果**：—

### OPT-11 触屏设备未识别为平板时，点一下礼物卡即触发「赠送」

- **项目 / 页面**：PC 直播间礼物面板；`src/components/chatBox/components/giftsPop/index.vue`。
- **现象**：2026-10-29 小米平板 8 开「桌面版网站」（TP-014 修复前，未识别为平板）adb 真实点击：打开礼物面板后点一下礼物卡，点击落在卡片上的「赠送」覆盖层，游客弹出登录框；已登录且钻石足够时会直接送出。

- **结论**：TP-014 后，Chrome 桌面版模式的安卓平板已能识别，不再触发；仍未识别的触屏设备（Windows 触屏笔记本、二合一电脑、非 Chrome 浏览器的桌面模式平板）预计同样触发，未实测。
- **影响 / 状态**：中高 / 已确认（安卓平板未识别时复现）；触屏笔记本待复核。
- **来源**：平板验收 TP-014。
- **建议**：赠送覆盖层只在 `(hover: hover)` 设备上随悬停出现，`(hover: none)` 或 `any-pointer: coarse` 时改为先点选中再赠送；或对所有设备统一改为先选中再赠送。需在一台 Windows 触屏笔记本上先复现。
- **处理结果**：—

### OPT-12 legacy 包以 `type="module"` 注入，现代浏览器报 `System is not defined`

- **项目 / 页面**：H5 全局；`nuxt.config` 第 6、118 行启用 `@vitejs/plugin-legacy`。
- **现象**：手机（安卓模拟器 Chrome 124）和小米平板（Chrome 156）打开 H5 首页、直播间，控制台均出现 `pageerror: System is not defined`。
- **原因**：`pnpm generate:prod` 产物 `200.html` 中 `-legacy*.js`（SystemJS 格式，供不支持 ES Module 的旧浏览器）以 `<script type="module">` 注入，而不是 `nomodule`，现代浏览器也会执行，找不到 `System`。
- **结论**：原有构建问题，与平板无关；未见页面功能受影响，但每次加载都报错，并多下载一份 legacy 包。
- **影响 / 状态**：低 / 已确认。
- **来源**：平板验收（手机、平板均复现）。
- **建议**：核对 Nuxt 3.11 与 `@vitejs/plugin-legacy` 的集成方式，确保 legacy 包以 `nomodule` 注入，或评估是否仍需支持旧浏览器。
- **处理结果**：—
