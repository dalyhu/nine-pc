## 一、当前分支主要解决的问题

**"退出登录"链路存在两类共存的时序 Bug，导致偶发出现：**

1. **退出接口返回 401 / 未成功登出**：`logoutService()` 在原实现里，是在 Vuex 已经 `commit('user/SET_USERINFO', {})` 之后才发起的。清空 Vuex 会使后续请求签名以 `visitor=0` 计算，鉴权层立刻拒绝——退出接口自己被自己刚清掉的身份签了名，因此常常打不通。
2. **界面残留登录态 / 半登录窗口**：
   - `SET_USERINFO` 内部对 "id 变化" 有一个 `setTimeout(() => reload(), 500)` 的延迟刷新。这 500ms 内 Vuex 是空的，但 UI 还没换掉，任何自动发起的请求（IM 重连、页面轮询、菜单点击）都会因空身份被 700/401 打回。
   - 调用方各写各的 `try/catch`：接口一失败就吞掉异常、不 reload，用户停在 "点了退出但没退出" 的状态。
   - `request-o.js` 收到 `code === 700` 时只 dispatch 了 `logout`，没有强制刷新，同样卡在残留登录态。
   - `App.vue` 里 `?isLogout=1` 分支只 `dispatch('logout')` 就完了，没有 await、没有 reload，用户从论坛跳回来后仍是登录态。
3. **`SpaceAndMine.vue` 有一份复制粘贴的 `handleSignOut`**，事实上模板从未调用，属于死代码，容易和 `LoginBtn.vue` 版本不同步。
4. **健壮性小坑**：
   - `IM.destroy()` 在 `IM.worker` 尚未创建时会抛 `Cannot read properties of undefined`。
   - `getMobile` 在 `infoData.mobile` 为 `undefined` 时会因 `.split` 直接崩掉页面。
5. **旧单测 `logout.spec.js`（445 行）** 基于"先 commit 再调接口"的老实现，与新语义完全不匹配，保留会造成误导，本分支一并删除。

## 二、总体方案

**核心思想：**
> **在身份仍然有效时发起退出接口，且不由 store 层触发 reload；本地 Vuex 状态由调用方通过整页刷新重建。**

将"清 Vuex → 触发 reload"这条隐式的、异步的、跨模块的路径，替换为"调用方显式 `await logout()` 之后立即整页导航"这条显式串行路径。这样：

- 退出接口的签名一定用真实身份发出，服务端能接住。
- 页面上不再有"空身份存活窗口"，因为下一步就是整页跳转，Vuex 从零初始化，不需要 mutation 参与。
- 调用点行为可预测：**任何入口的退出 = `dispatch('logout')` + `window.location.reload/replace`**，两步。

## 三、逐文件改动详解

### 1. `src/store/index.js` —— `logout` action 重写

```js
async logout() {
  try {
    // 退出接口必须在身份仍然有效时发出，
    // 否则签名用 visitor=0 计算，会被鉴权层拒绝
    await logoutService()
  } catch (error) {
    console.error(error)
  }

  // 接口成功与否都要完成本地登出。
  // 刻意不 commit Vuex:commit 会触发 SET_USERINFO 里的延迟 reload,
  // 并在页面存活期间制造一段空身份窗口,使窗口内的请求全部被拒。
  // 调用方随后会整页导航,Vuex 状态由此重建。
  try {
    IM.destroy()
    removeUrlParams('invite_code')
    localStorage.removeItem('urlInviteCode')
    localStorage.setItem('userInfo', '{}')
    localStorage.removeItem('visitorInfo')
  } catch (error) {
    console.error(error)
}
}
```

关键点：
- 调整顺序：**先调接口，再清本地**。
- **移除了 `commit('user/SET_USERINFO', {})` 与 `commit('setVisitorInfo', {})`**，把 Vuex 交给调用方后续的整页刷新去重建。
- 移除了对 `isSignOutService`（原本用于确认是否已登出）的依赖，删除了对应 import。原逻辑要么接口正常、要么不正常；无论哪种，本地都必须完成登出，二次确认反而放大了失败窗口。
- 本地 `userInfo` 直接写 `'{}'`，与 `SET_USERINFO({})` 时 mutation 里落盘的形态保持一致，避免下一次读时反解密拿到旧对象。
- 顺手修一处 NPE：
  ```js
  // 前
  return state.user.infoData.mobile.split('-')[1] || ''
  // 后
  return state.user.infoData.mobile?.split('-')[1] || ''
  ```

### 2. `src/App.vue` —— `?isLogout=1` 分支加 await + reload

从论坛跳回主站时会附带 `?isLogout=1`，用于让主站也执行一次退出。改动：

```diff
 if (isLogin.value) {
-  store.dispatch('logout')
+  await store.dispatch('logout')
+  // logout 不再 commit Vuex,必须由调用方整页刷新重建 store,否则界面仍是登录态
+  window.location.reload()
 }
```

对应第 3 个提交（`b92cf99e`）——即使 logout 内部走了 catch 分支（接口报错），外部依旧要 reload，才能保证 UI 一致。

### 3. `src/utils/request-o.js` —— 700 错误码强制刷新

```diff
 } else if (res.code === 700) {
   ElMessage.error(res.msg || '登录状态失效，请您重新登录')
-  store.dispatch('logout')
+  // logout 不再 commit Vuex,必须整页刷新重建 store,
+  // 否则界面残留登录态、后续请求继续用失效 token 签名
+  store.dispatch('logout').finally(() => {
+    setTimeout(() => window.location.reload(), 1500)
+  })
 }
```

- `1500ms` 延迟：留给 `ElMessage` 展示"登录已失效"的提示，用户可读。
- 用 `.finally`：不管 logout 内部走 try 还是 catch，都会 reload。

### 4. `src/layout/components/Navbar/LoginBtn.vue` —— 头部"退出"按钮

```diff
 const handleSignOut = async () => {
-  try {
-  await store.dispatch('logout', 'loginOut')
-    window.location.reload()
-  } catch (error) {
- ElMessage.error(error.msg || '退出登录失败')
-  }
+  await store.dispatch('logout')
+  window.location.reload()

```

- 去掉 `'loginOut'` payload：新 action 不再需要它。
- 去掉 `try/catch`：`logout` 内部已自己 catch 所有异常并做本地登出；外层 catch 只会让用户看到"退出失败"但实际上已经登出，属于误报。

### 6. `src/views/personalCenter/mainMenu.vue` —— 个人中心退出走整页导航

```diff
 }).then(async () => {
-  try {
-    await store.dispatch('logout', 'loginOut')
-    $router.replace('main')
-  } catch (error) {
-    ElMessage.error(error.msg || '登出失败')
-  }
+  await store.dispatch('logout')
+  // 整页加载而非 SPA 内跳转:SPA 挂载会在身份清空后立刻打出一批请求
+  window.location.replace(`${import.meta.env.BASE_URL}main`)
 })
```

将 `router.replace('main')` 换成 `window.location.replace(...)`——这是本方案的第二个关键点：**SPA 内部路由 `replace` 只是切换 view，Vuex 状态还在**，切走的新页面 mount 时会立即用空身份打一批请求。整页 `location.replace` 强制走完整启动流程，从 localStorage 重建 Vuex，语义干净。

### 7. `src/utils/im/index.js` —— 防御性可选链

```diff
 static destroy() {
-  IM.worker.postMessage({ action: 'destroy' })
+  IM.worker?.postMessage({ action: 'destroy' })
 }
```

游客态或 IM 尚未初始化时 `IM.worker` 可能为 undefined。退出流程会调用 `IM.destroy()`，此前会因此在控制台抛错、遮盖真正的错误。

### 8. `src/utils/request.js` —— 构建产物（混淆的 axios 拦截器）

新老两份文件都是打包后的加密请求库。差异对应 `request-o.js` 里"code === 700 后延迟 1500ms 整页刷新"的逻辑升级；产物不需人工审阅。

### 9. `src/__tests__/store/logout.spec.js` —— 删除 445 行旧测试

原测试断言 `commit('user/SET_USERINFO', {})` 会先于 `logoutService()` 执行、断言存在 `isSignOutService` 的二次校验路径。新实现两点都改了；这些断言只会阻塞后续 CI。删除后待新一轮 Q3 测试计划补上对应用例（建议覆盖：先调接口后清本地、Vuex 保持不变、IM.destroy 幂等、request-o 700 延迟 reload）。
