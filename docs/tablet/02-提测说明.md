## 一、这次改了什么

| | 一期（已上线测试环境） | 二期（本次提测） |
|---|---|---|
| 平板横屏 | 进 PC，PC 首页、直播间已适配触摸 | 不变 |

**页面范围**：
- **精细适配**（按设计效果验收）：H5 直播首页、H5 直播间；PC 首页、PC 直播间（一期）。
- **兜底适配**（只看「能用」）：其余所有 H5 页面——不留白、无横向滚动、图片不变形、内容不重叠。**好不好看不提 bug**，精细适配放在三期。

PC 和 H5 必须在同一个域名下测试（PC 在 `/`，H5 在 `/m`），否则跨站跳转测不了。

## 二、规则速览

完整规则见 01；测试只需记住下面五步，每一步只在上一步的结果内细分：

1. **是不是平板**：iPad（默认或移动版网站）、安卓 / 鸿蒙平板、安卓平板开「桌面版网站」认作平板；手机、折叠屏手机、电脑都不是。手机开「桌面版网站」不会被认成平板。
2. **进 PC 还是 H5**：手机 → H5；电脑 → PC；平板竖屏 → H5，横屏宽 ≥ 854 → PC，横屏宽 < 854 → H5。
3. **H5 是否宽屏**：屏幕短边 ≥ 600 时启用「字号封顶 + 宽度铺满」，`<html>` 带 `data-h5-wide-screen`。普通手机永远不启用。
4. **H5 直播间上下还是左右**：宽屏已启用、有视频，且可用宽 ≥ 600、可用高 ≥ 500、宽 ÷ 高 ≥ 0.9 时左右，否则上下。左右时 `<html>` 带 `data-h5-live-wide`。
5. **分隔线**：直播间左右布局时，两栏之间有可拖动的分隔线（常驻小抓手），**默认打开**；左右拖动调整视频与聊天的宽度，两栏都不小于 300，松手后记住。

**什么时候判断**：整页打开（输地址、刷新、外链进入）时判断第 1、2 步；使用中转屏、展开 / 合上**不跳站**，只在推荐版本变了时出顶部横条。第 3、4 步在使用中实时跟随尺寸变化。

## 四、典型示例

拿到一台设备，按下面的方式对号入座（括号里是对应截图，见第五节）：

**示例 1：11 寸 iPad 竖着拿（T-M1，820×1180）**
- 打开 PC 首页 `/main` → 自动进 H5 直播首页；打开 H5 任意页面 → 留在 H5。
- H5 字号接近手机（不再整页放大），宽度铺满、两侧无白边；首页「正在直播」卡片每行 3 张。
- 直播间上下结构：视频满宽在上（16:9），聊天在下，一屏能看到多条消息。
- 转成横屏 → 顶部出现「当前空间适合大屏版 / 切换大屏版」，不会自己跳。
- 截图：`T-M1_竖屏_820x1180_H5首页`、`T-M1_竖屏_820x1180_H5直播间`；改动前对比 `对比-改动前_T-M1_竖屏_…`。

**示例 2：11 寸 iPad 横着拿（T-M1，1180×820）**
- 打开 H5 直播间 → 自动进 PC 同一主播的直播间；PC 页面导航菜单点一下打开（不靠鼠标悬停），礼物点一下只选中、点「赠送」才送出。
- 转成竖屏 → 顶部出现「当前空间更适合移动版 / 切换移动版」。
- 截图：`T-M1_横屏_1180x820_PC首页`、`T-M1_横屏_1180x820_PC直播间`。

**示例 3：折叠屏展开横着拿（Galaxy Z Fold8 Ultra，834×626）**
- 仍是 H5（手机身份；即使 Chrome 报平板身份，宽 834 < 854 也留在 H5）。
- 直播间**左视频、右聊天**：右栏默认 300 宽，其余给视频（534），视频上下居中；聊天输入框、礼物、发送一屏可见。
- 两栏中间有**可拖动的分隔线**（竖排三个点）：按住左右拖，聊天栏在 300～534 之间变化，松手后记住，下次进来还是这个宽度；拖动时手指划过视频不会暂停、不会跳页。
- 折叠起来（合上）→ 立即变回手机样式；再展开 → 立即变回左右，不用刷新。
- 截图：`Fold8Ultra_展开横_三星浏览器_834x626_H5直播间`；改动前对比 `对比-改动前_Fold8Ultra_展开横_…`（改动前视频占满整屏，聊天要往下滑）。

**示例 4：窄书本式折叠屏展开竖着拿（Galaxy Z Fold8，约 616×740）**
- H5，字号封顶、铺满；但屏幕偏竖长（宽 ÷ 高 0.83 < 0.9），直播间保持**上下**结构，没有分隔线。横过来拿就变成左右。
- 这是规则内的结果，不是 bug。尺寸为估算，有真机时请记录实际尺寸。
- 截图：`GalaxyZFold8_展开竖_估算_616x740_H5直播间`。

**示例 5：折叠屏合上 / 普通手机（如 360×658、390×750）**
- 和改动前完全一样：没有宽屏、没有横条、没有分隔线；转回竖屏照旧整页刷新。
- 截图：`Fold8Ultra_合上_360x658_H5首页`、`Fold8Ultra_合上_360x658_H5直播间`。

## 六、怎么测

### 1. 准备：Chrome 模拟设备

1. 打开开发者工具（`F12`），切到设备模式（`Cmd/Ctrl + Shift + M`），设备下拉 → `Edit…` → `Add custom device…`。
2. 按第三节第 1 部分的表每行加一个设备：宽高填竖屏值，像素比 `2`，`User agent type` 选 **Mobile**（不选就没有触摸，认不成平板），UA 按下面整串粘贴：

```text
iPad：Mozilla/5.0 (iPad; CPU OS 18_5 like Mac OS X) AppleWebKit/605.1.15 (KHTML, like Gecko) Version/18.5 Mobile/15E148 Safari/604.1
安卓平板：Mozilla/5.0 (Linux; Android 15; K) AppleWebKit/537.36 (KHTML, like Gecko) Chrome/138.0.0.0 Safari/537.36
```

   也可以完全退出 Chrome 后在 `pc-main` 根目录运行 `python3 docs/tablet/import-chrome-devices.py` 一次导入。
3. 横屏点工具栏的旋转按钮即可。**切换模拟设备后一定要刷新页面**；只点旋转不用刷新（旋转模拟使用中转屏，用来测横条和左右布局切换）。
4. 折叠屏：用 Chrome 自带的 `Galaxy Z Fold 5`（展开、折叠都测），或响应式模式输入第三节第 2 部分明细表的视口。**注意**：Chrome 模拟中屏幕尺寸等于窗口尺寸；B3 这类「屏幕大、窗口小」的分屏场景只能真机测。
5. 自检：刷新后在控制台执行

```js
JSON.stringify({ touch: navigator.maxTouchPoints, w: innerWidth, h: innerHeight, marks: [...document.documentElement.attributes].map(a => a.name).filter(n => /data-(tablet|h5)/.test(n)) })
```

   平板在 PC 页应有 `data-tablet-pc`，在 H5 页应有 `data-tablet-h5`；宽屏时有 `data-h5-wide-screen`，直播间左右时有 `data-h5-live-wide`。手机、电脑上一个都不应出现。

## 八、测试时容易误以为是 bug

1. **防循环**：10 秒内自动跳转 2 次就停在当前版本。快速连续刷新、频繁切换模拟设备时可能「该跳不跳」，新开标签页或等 10 秒再试。横条的「切换」不受限制。
2. **横条不出现**：本标签页点过关闭就不再出现，要重测请新开标签页。
3. **页面空白、提示「操作太快」**：测试环境有访问频率限制，等几分钟再刷新，不要清除网站数据。截图、巡检请用普通 Chrome 手动操作，不要用自动化工具批量打开 PC 页面。
4. **部署后还是旧样式**：有 Service Worker 缓存，刷新一次即可。
5. **根域名循环刷新**：部署前访问过旧版本的设备，清一次站点数据或用无痕窗口。

1. 设备：模拟设备名（如 T-M1）或真机型号、浏览器及模式（iPad 是否「请求桌面网站」、安卓是否开「桌面版网站」），横屏还是竖屏，折叠屏是展开还是合上。
