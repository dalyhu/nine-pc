# 平板与折叠屏适配 · 方案与规则

> 本文是平板、折叠屏适配的**唯一规则来源**（一期 + 二期合并，2026-11-08 整理）。规则以代码为准：识别在 `pc-main/public/static/assets/tablet-profile.js`（与 `h5-main/utils/tablet-profile.js` 逐字一致），PC 入口在 `pc-main/index.html`，H5 入口在 `h5-main/plugins/init.client.js`，宽屏判定在 `h5-main/utils/tablet-wide-screen.js`。
> 相关文档：[02 提测说明](02-提测说明.md)（给测试的入口，含截图）、[03 问题记录](03-问题记录.md)（TP 编号）、[04 验收与开发记录](04-验收与开发记录.md)。

## 一、目标与范围

网站有两套页面：PC（`/`，`pc-main`）和 H5（`/m`，`h5-main`），同一个域名。原来只按「是不是手机」分流，所有平板一律进 PC，折叠屏展开后进 H5 但整页按宽度放大。

| 期 | 解决什么 | 状态 |
|---|---|---|
| 一期 | 认出平板，按方向分流：横屏看 PC、竖屏看 H5；PC 首页、直播间的触摸与布局适配 | 已实施 |
| 二期 | H5 在大屏上**字号封顶、宽度铺满**；折叠屏等接近方形的大屏，H5 直播间改为**左视频、右聊天** | 已实施（2026-11-07 真机验收） |
| 三期 | 其余页面的精细适配（见第九节） | 未开始 |

**二期覆盖范围**：
- **精细适配**：H5 直播首页（直播列表）、H5 直播间；PC 首页、直播间（一期）。
- **兜底适配**：其余所有 H5 页面——只保证不留白、无横向滚动、图片不变形、内容不重叠，不做版式设计。
- **不变**：手机、电脑的分流与显示和改动前完全一致。

### 整体思路（三句话）

1. **大屏平板横屏看 PC**：宽度足够放下 PC 直播间（≥ 854），触摸和布局已适配。
2. **平板竖屏看 H5**：H5 字号封顶到「相当于 540 宽手机」，宽度铺满屏幕，多出的宽度靠多列重排使用，不再整页放大。
3. **折叠屏展开看 H5，直播间左右分栏**：接近方形的屏幕上，左边视频、右边聊天（参考 Twitch），聊天不再被挤成一小条。

## 二、五层判断

每次整页打开页面，依次判断五层，下层只在上层结果内细分，不改上层结论：

| 层 | 回答什么 | 依据 | 章节 |
|---|---|---|---|
| ① 身份 | 手机、平板还是电脑 | 浏览器 UA 与少量设备信息 | 第三节 |
| ② 版本 | 进 PC 还是 H5 | 手机 → H5；电脑 → PC；平板按方向和宽度 | 第四节 |
| ③ 宽屏 | H5 是否启用「字号封顶 + 宽度铺满」 | 屏幕短边 ≥ 600 | 第五节 |
| ④ 直播间 | H5 直播间上下还是左右 | ③ 已启用，且可用宽 ≥ 600、可用高 ≥ 500、宽高比 ≥ 0.9 | 第六节 |
| ⑤ 手柄 | 左右布局是否显示可拖动分隔线 | ④ 为左右、开关开启、可拖动范围 ≥ 40 | 第七节 |

③④⑤ 只在 ② 为 H5 时生效，只读尺寸、不读 UA、不触发跳转；PC 页面不加载 H5 样式。

## 三、① 身份：怎么认出平板

满足任一条件即为平板：

| # | 情况 | 判断条件 |
|---|---|---|
| 1 | UA 本身标明是平板：iPad「请求移动版网站」（UA 带 `iPad`）、安卓 / 鸿蒙平板（UA 不带 `Mobile`） | UA 解析库 `ua-parser` 得出 `device.type === 'tablet'`，且 UA **不带** `Macintosh` |
| 2 | iPad 默认模式（Safari「请求桌面网站」，UA 伪装成 Mac） | UA 带 `Macintosh`，`navigator.platform === 'MacIntel'`，有触摸（`maxTouchPoints > 0`），且**屏幕短边 ≥ 600** |
| 3 | 安卓开「桌面版网站」（UA 伪装成 Linux 电脑） | UA 带 `X11; Linux x86_64`，`navigator.platform` 以 `Linux arm` / `Linux aarch` 开头，有触摸，且**屏幕短边 ≥ 600** |

- **不是「尺寸够大 + 有触摸」就算平板。** 条件 2、3 必须配合 UA 里的破绽：条件 2 是「UA 自称 Mac 却能触摸」，条件 3 是「UA 自称 x86 电脑但芯片是 ARM」。只看触摸和尺寸，会把带触摸屏的 Windows 笔记本误认成平板。
- **屏幕短边 ≥ 600 用来排除手机**：手机开「请求桌面版网站」时 UA 也长这样（iPhone 报 Mac，安卓报 Linux），手机屏幕短边不超过约 500，iPad 最小 744（TP-014、TP-118）。屏幕尺寸读不到时不认作平板。
- 条件 1 排除 Mac UA，是因为解析库在浏览器里会把「Mac UA + 触点 > 2」自行改判成 iPad，桌面版 iPhone 也会中招；Mac UA 统一交给条件 2 按屏幕判断（TP-118）。
- **折叠屏、三折叠不单独识别**：按浏览器实际报的身份走——报手机（UA 带 `Mobile`）就是手机，报平板就是平板。
- 识别成平板后：PC 页面 `<html>` 带 `data-tablet-pc`，H5 页面带 `data-tablet-h5`；PC 悬停菜单改为点击，并应用平板样式。

**认不出的情况**（按原逻辑处理，与改动前一致，不是缺陷）：

| 情况 | 结果 |
|---|---|
| 安卓平板在非 Chrome、非小米浏览器里开桌面模式 | 按电脑进 PC，无平板适配 |
| 平板浏览器发送带 `Mobile` 的手机 UA（部分国产浏览器） | 按手机进 H5 |
| 华为平板 UA 为 `HUAWEI <型号> Build/…` 格式 | 解析为手机，进 H5 |
| Windows 上用 Chrome 模拟 iPad 默认的 Mac UA | 平台不是 `MacIntel`，识别不了；模拟测试统一用 iPad 移动版 UA |

## 四、② 版本：进 PC 还是 H5

### 1. 手机与电脑（原逻辑，未改）

| 设备 | 结果 |
|---|---|
| 手机（含折叠屏手机，UA 解析为 `mobile`） | H5，不看屏幕大小和方向 |
| 电脑、Mac、Windows 触屏本 | PC |

PC 入口：手机打开 `/room/ID`、`/live?uid=` 进 H5 直播间，其余进 H5 首页。H5 入口：电脑打开 H5 直播间进 PC 直播间，其余进 PC 首页。

### 2. 平板

宽、高取页面可用视口 `innerWidth × innerHeight`：

| 平板状态 | 进 |
|---|---|
| 竖屏（高 > 宽），任何尺寸 | H5 |
| 横屏，宽 ≥ 854 | PC |
| 横屏，宽 < 854 | H5 |

**854 的来源**：PC 直播间平板最小空间 = 视频 480 + 聊天 260 + 左右留白 104 + 间距 10。

**各页面的行为**（整页打开时；站内点击不判断）：

| 整页打开的页面 | 平板推荐 H5（竖屏等） | 平板推荐 PC（横屏宽 ≥ 854） |
|---|---|---|
| PC 首页、直播间（`/`、`/main`、`/live`、`/room/*`，精确匹配） | 进 H5 对应页 | 留在 PC |
| PC 其他页面 | 留在 PC；用户点了「切换移动版」才进 H5，没有对应页进 H5 直播首页 | 留在 PC |
| H5 首页、直播首页、直播间（`/m/`、`/m/live/idx`、`/m/live/detail`） | 留在 H5 | 进 PC 对应页 |
| H5 其他页面 | 留在原页 | 进 PC 首页 `/main` |

- **精确匹配**：`/live/`（多一个斜杠）这类地址不算生效页，按「其他页面」处理，避免丢失主播。
- **参数**：跳转复用原有手机 / 电脑的跳转代码，`channel_code`、`invite_code`、`token`、`userId`、`redirectTo` 携带规则与原来一致；直播间映射到同一个主播。
- **跳转用「替换」**：按返回键回到上一个页面，不会被弹回来。
- **登录、退出**：H5 登录、退出后原来写死跳 `/live/idx`、`/home/idx`，平板会落到 PC 的空白页；平板分支改为跳带 `/m` 的地址，手机、电脑不变（TP-115）。
- **根路径 `/`**：站点原有规则会把移动设备访问 `/` 转到一个 H5 壳子页；平板分流到 PC 时直接跳 `/main`，壳子内的 H5 跳顶层窗口，因此**不依赖、也不需要修改服务器配置**。代价是平板横屏直接打开 `/` 会先短暂显示 H5 再进 PC（TP-104）。

### 3. 使用中转屏：顶部切换横条

- **不自动跳转**：直播站用户转屏频繁，跳站会中断观看。
- 推荐版本因转屏、窗口变化、退出全屏、输入框失焦而改变，且与当前版本不一致时，在顶部显示横条：
  - 推荐 PC：「当前空间适合大屏版」+「切换大屏版」
  - 推荐 H5：「当前空间更适合移动版」+「切换移动版」
- **H5、PC 两边所有页面都提示**（TP-116）；手机、电脑永不显示。
- **不显示的时候**：刚进入页面（只记录基线）；本会话点过关闭（同一标签页内不再出现）；全屏中（退出后重新判断）；输入框正在输入（失焦后重新判断）。
- **点切换**：写入一次性切换标记 `x9:tablet-switch`（`sessionStorage`），重新加载，由入口按用户选定的版本跳转。H5 页面去 PC 对应页，没有对应页进 `/main`；PC 首页、直播间、隐私协议、下载页去 H5 对应页，其余进 H5 直播首页。

### 4. 防循环与发布

- **防循环**：平板 10 秒内自动跳转达到 2 次就停在当前版本，不再跳。用于兜住发布不同步、缓存旧代码等情况。横条的「切换」不受限制。
- **存储容错**：所有 `sessionStorage` 读写都捕获异常；读取失败按「无记录」处理，写入失败静默忽略，任何情况都不中断页面初始化。
- **发布顺序**：H5 先发或两边同时发。两边的识别脚本必须逐字一致，否则同一设备在两边结论不同，会来回跳（由防循环兜底停下）。
- **回滚**：两个项目分别回退即可，建议同时进行。

### 5. 其他入口行为

| 行为 | 手机 | 平板 |
|---|---|---|
| H5「转回竖屏就刷新页面」 | 保持原样 | 关闭（平板转屏不刷新） |
| H5 iOS 双指缩放 / 双击放大拦截 | 保持原样 | 对 Mac UA 的 iPad 同样生效 |
| H5 直播间网页全屏 | 原样 | 同样可用（平板在 H5 里不是 `IS_MOBILE`，网页全屏条件改为「手机或平板」） |

## 五、③ H5 宽屏：字号封顶、宽度铺满

### 1. 什么时候启用

- **屏幕短边 ≥ 600**；或屏幕尺寸不可信（视口比屏幕还大，如 iPhone Duo 展开后仍报外屏尺寸）时，**视口短边 ≥ 500**。
- 且浏览器完整支持所用的 CSS 写法（`var()`、`min()`、`max()`、`calc()`），否则不启用，表现与改动前一致。
- 页面加载、窗口变化、转屏、折叠屏展开 / 合上时持续判断。启用时 `<html>` 带 `data-h5-wide-screen`。
- **普通手机零变化**：手机竖屏、横屏、折叠屏合上永不启用；所有新样式只写在 `html[data-h5-wide-screen]` 下。
- 不参与身份识别和分流。

### 2. 规则

1. **字号封顶**：字号单位 `--h5-u = min(1vw, 5.4px)`，设计稿尺寸（字号、图标、间距、圆角、按钮高度）最多相当于 540 宽屏幕，约为 390 宽手机的 1.4 倍。
2. **宽度铺满**：页面主体、顶栏、底栏、吸底栏、悬浮按钮都以页面视口宽度为准，任何宽度下都不出现左右留白和横向滚动。
3. **多出的宽度靠重排**（都是宽度的连续函数，不按机型写特例）：

| 规则 | 内容 |
|---|---|
| R1 满宽元素 | 手机上占满一行的元素，宽屏下占满容器宽度 |
| R2 卡片网格 | 直播卡片按可用宽度自动排列：最小宽度 36 个单位（194.4px），列间距 2.4 个单位。实测 540 宽 2 列、669～800 宽 3 列、1024 宽 4 列、1200 宽 5 列 |
| R3 图片、横幅、视频 | 宽度随所在容器，高度按原宽高比，不变形、不裁主体 |
| R3a 上下布局的视频 | 铺满宽度、16:9，高度不超过直播区的一半；超宽矮窗口按高度上限，两侧黑边属于播放器 |
| R4 轮播 | 单张宽度随容器计算，不露半张、不偏一侧 |
| R5 文字区 | 定宽截断的文字（如赛事队名）随容器伸展 |
| R6 横向滑动列表 | 保持原卡片大小，宽屏下自然多露出几张 |

4. **浮层**：蒙层、全屏视频、图片预览铺满整个屏幕；居中弹窗内容框宽度 `min(540px, 100%)`、在屏幕中居中（周围是蒙层，不算留白）；底部弹出层（礼物面板、分享）满宽。
5. **禁止**：用纯色或背景图填两侧冒充铺满；按具体机型、尺寸写分支；给应用祖先加 `transform`。

## 六、④ H5 直播间：上下还是左右

### 1. 触发条件

未处于左右布局时**同时满足「进入」列**才进入；已处于时**任一条落入「退出」列**即退出（进入、退出之间留有差值，地址栏收放、细微尺寸变化不会来回切换）：

| # | 量 | 进入 | 退出 |
|---|---|---|---|
| 0 | 宽屏（第五节）已启用 | 已启用 | 未启用 |
| 1 | 有视频（`hidevideo` 为假） | 为假 | 为真 |
| 2 | 可用宽 = `innerWidth` − 左右安全区 | ≥ 600 | < 580 |
| 3 | 可用高 = `innerHeight` − 上下安全区 | ≥ 500 | < 460 |
| 4 | 宽高比 = 可用宽 ÷ 可用高 | ≥ 0.9 | < 0.85 |

- 宽高比区分形状：竖长条（手机、平板竖屏，0.5～0.81）保持上下；接近正方形或横向（折叠屏展开 0.97～1.44）用左右。
- 可用高排除很宽但很矮的手机横屏。
- 不看 UA、不看是不是折叠屏。

### 2. 空间分配

- **右栏（聊天）默认 300**，左栏（视频）= 可用宽 − 右栏，下限 300。右栏下限由聊天输入行决定：300 宽时输入框约 89 宽，再窄基本不可用。
- 左栏视频 16:9、垂直居中；右栏依次为平台广告条、标签栏、聊天（占满剩余高度，输入区在底部）。
- 浮层（下载提示、礼物面板、弹层、Toast）保持原位置，不归属任一栏。

| 可用宽 | 右栏 | 左栏 / 视频 |
|---|---|---|
| 600（下限） | 300 | 300 / 300×169 |
| 692（Pixel 10 Pro Fold） | 300 | 392 / 392×221 |
| 752（Fold8 Ultra 竖着拿） | 300 | 452 / 452×254 |
| 834（Fold8 Ultra 横着拿） | 300 | 534 / 534×300 |
| 1000 | 300 | 700 / 700×394 |

### 3. 什么时候重新判断

- 窗口变化（150ms 防抖）、宽屏状态变化、`hidevideo` 变化、退出全屏后一次、输入框失焦后。
- **全屏期间、输入期间不判断**：键盘弹起收起过程不切换、不闪烁，输入框完整可见；失焦后等高度稳定再统一判断一次。
- 手机 UA 转回正竖屏时整页刷新（原有行为）；折叠屏展开 / 合上由窗口变化实时切换。
- 直播间卸载时清理所有监听与标记。左右布局时 `<html>` 带 `data-h5-live-wide`。

## 七、⑤ 可拖动分隔线

- 只在 H5 直播间**处于左右布局**时出现；分隔线上有常驻小抓手，不弹引导。
- 按住左右拖动，右栏宽度跟手变化，范围 **右栏 ≥ 300、左栏 ≥ 300**；可拖动范围小于 40（可用宽 < 640）时不显示；全屏时隐藏。
- 松手后记住宽度（本地存储 `x9:h5-live-split`），下次按当前范围重新限制；存储不可用时用默认 300，不影响直播间。
- 防护：拖动时临时让播放器不接收触摸；松手、取消、切后台、失焦、离开直播间都会结束拖动并恢复播放器触摸；超过 3 秒没有移动事件就取消本次拖动。
- **开关**：**默认打开**（2026-11-08 触摸复测通过后决定，见 04 E2～E4）。只由代码总开关控制，不提供地址参数：需要关闭时把 `h5-main/utils/tablet-live-split.js` 的 `LIVE_SPLIT_ENABLED` 改为 `false` 并重新发布 H5。

## 九、三期：其余页面精细适配

二期其余 H5 页面只做了兜底（不留白、无横向滚动、不变形、不重叠）。三期按重要程度逐页调视觉，候选清单与发现位置见 [04](04-验收与开发记录.md) 第三节。新增页面或组件写死宽度时，由回归里的留白检测拦下。

## 十、改动原则与开发规范

### 1. 原则

1. **非平板设备的分流结果不变**，只在入口处增加「已识别平板」的分支；手机、电脑走不到新的分流代码。
2. **两个项目的识别脚本逐字一致**，单元测试校验。
3. **二期所有 H5 新样式只在 `data-h5-wide-screen` / `data-h5-live-wide` 下生效**；普通手机拿不到这两个标记，手机回归用例逐项零差异。
4. **不改业务逻辑**：播放、聊天、礼物、弹层、全屏、返回键不动；左右布局只调整排列，不改模板结构。
5. **不新增引导、提示类弹窗**；能靠布局解决的不靠提示。

### 2. 新页面纳入适配时的检查

- 纳入平板分流：把路径加进 `tablet-profile.js` 的 `inScope`（PC、H5 两份同步，精确匹配，H5 写去掉 `/m` 后的路径）。
- PC 样式写在 `src/styles/tablet.scss` 的 `html[data-tablet-pc]` 下；H5 宽屏样式写在 `html[data-h5-wide-screen]` 下；普通 PC、手机的表现不得变化。

| # | 检查（PC 平板） | 改法 |
|---|---|---|
| T-1 | `trigger="hover"` 的弹层、下拉、提示 | 平板改为 `click` |
| T-2 | 弹层触发元素自身也有点击行为 | 平板上阻止冒泡 |
| T-3 | 悬停才出现的操作按钮（如礼物「赠送」） | 平板先点选中，再单独点操作；导航入口提供可见触摸入口 |
| T-4 | 关闭、图标按钮点击区 | 不小于 44×44（用内边距扩大） |
| T-6 / T-7 | 超宽内容、横向标签被截断 | 容器 `overflow-x: auto`，子项不收缩 |
| T-8 | 固定高度侧栏，矮屏够不到底 | `calc(100dvh - 顶栏)` + 纵向滚动 |
| L-1 | 写死的 `min-width`、`1200px` 等 | 平板作用域降低最小宽度或允许横向滑动 |
| L-2 | 主内容 + 侧栏 | 侧栏用 `clamp()` 设上下限，主内容保底 |
| L-3 / L-4 | 一行固定 N 个卡片、标题行挤压 | 减列或换行；信息与操作分行 |

| # | 检查（H5 宽屏） | 改法 |
